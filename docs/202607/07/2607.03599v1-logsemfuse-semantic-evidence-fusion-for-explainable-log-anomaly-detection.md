## 摘要
日志异常检测对于现代软件系统的可靠性监控和故障诊断至关重要。现有的基于模型的检测器能提供有用的异常信号，但仍可能遗漏异常会话，且通常只输出评分或标签，而非决策背后的操作语义。这种语义证据的缺失限制了其解释会话为何异常的能力，即使最终异常标签正确。在实际中，这一差距至关重要，因为操作人员需要区分紧急故障与良性偏差，并将可疑会话追溯到具体操作行为。大语言模型（LLM）可以恢复更丰富的日志语义，但将其用作独立检测器或反复生成自由文本解释成本高昂且难以复用。我们提出LogSemFuse，一种证据引导的即插即用框架，在不替换原有流水线的情况下增强现有骨干检测器。LogSemFuse将骨干预测与来自局部事件模式、基于LLM的语义推理以及聚类推导的可执行规则中的可复用语义证据相结合，生成异常决策和基于证据的解释。输出结果报告最终标签及其支持的语义证据，如触发的局部模式、触发的规则和LLM推理依据。我们在HDFS、BGL和Liberty上使用DeepLog、LogAnomaly、LogBERT和NeuralLog作为骨干进行评估。LogSemFuse改进了所有非完美基线，保留了已完美的案例，恢复了98.8%的骨干假阴性，并在人工研究中产生了比直接LLM解释更受偏好的解释。这些收益仅需适度和稳定的推理时间开销，表明语义增强可以在不增加大量运行时成本的情况下提高检测有效性和可解释性。

## Abstract
Log anomaly detection is critical for reliability monitoring and failure diagnosis in modern software systems. Existing model-based detectors provide useful anomaly signals, but they can still miss anomalous sessions and typically expose only scores or labels rather than the operational semantics behind a decision. This lack of semantic evidence limits their ability to explain why a session is anomalous, even when the final anomaly label is correct. The gap matters in practice because operators need to distinguish urgent failures from benign deviations and trace suspicious sessions back to concrete operational behavior. LLMs can recover richer log semantics, but using them as standalone detectors or repeatedly generating free-form explanations can be costly and difficult to reuse. We present LogSemFuse, an evidence-guided plug-in framework that enhances existing backbone detectors without replacing their original pipelines. LogSemFuse combines backbone predictions with reusable semantic evidence from local event patterns, LLM-based semantic reasoning, and cluster-derived executable rules to produce both anomaly decisions and evidence-based explanations. The resulting output reports the final label together with the semantic evidence that supports it, such as fired local patterns, triggered rules, and LLM rationale. We evaluate LogSemFuse on HDFS, BGL, and Liberty using DeepLog, LogAnomaly, LogBERT, and NeuralLog as backbones. LogSemFuse improves every non-perfect baseline, preserves the already perfect case, recovers 98.8% of backbone false negatives, and produces explanations preferred over direct LLM explanations in a human study. These gains require only modest and stable inference-time overhead, showing that semantic augmentation can improve detection effectiveness and interpretability without imposing large runtime costs.

## 2. 方法论

### 核心思想
LogSemFuse是一个即插即用的语义增强框架，保留骨干检测器的原始训练和推理流水线，通过融合四种独立信号（骨干预测、局部事件模式、LLM语义推理、聚类派生规则）生成最终异常决策，并输出支持该决策的多层次语义证据作为解释。

### 关键技术细节

#### a. 输入表示与骨干接口
- 日志先经Drain解析为模板，映射为EventID序列；按时间戳排序并分组成会话（session）；对窗口型骨干还需构建固定窗口。
- 骨干检测器在EventID序列上按原始方式训练和预测。LogSemFuse在决策层融合信号，不修改骨干。

#### b. 训练时可复用证据构建

**模块I：局部事件模式挖掘（Local Event-Pattern Mining）**
- 从训练会话的EventID序列中提取unigram、bigram、trigram候选模式。
- 统计每个模式在异常会话和正常会话中的支持度（session级出现频次），计算提升度（lift）。
- 在验证集上筛选：去除在正常会话中误报过多或F1低的模式，保留的模式构成局部事件模式库 `K_ngram`。
- 推理时，如果目标会话的EventID序列包含任一模式（连续子序列），则触发信号 `s_n(x)=1`，并记录匹配的模式作为证据。

**模块II：聚类派生规则库构建（Cluster-Derived Rule Bank）**
- 将训练集中异常会话用TF-IDF向量化，再用HDBSCAN聚类（无需预设簇数），将相似异常行为分组。
- 对每个簇，将代表性会话、EventID-模板映射、簇统计信息提供给LLM，要求LLM输出结构化规则候选人（包含名称、条件（if_any/if_all）、解释说明），规则原语包括`contains_ngram`、`ordered_subset`、`min_count`、`absent_within`。
- 对LLM输出的规则进行模式校验（语法、类型、与模板一致性），验证通过的规则存入规则库 `K_rule`。
- 推理时，直接对会话EventID序列执行规则，若任意规则触发则信号 `s_r(x)=1`，并记录触发规则及对应簇解释。

#### c. 推理时LLM语义推理与解释
- 对每个（首次出现的）会话，调用LLM（固定提示词），要求返回结构化输出：expected（期望行为）、observed（观察行为）、is_high_risk（是否高风险）、confidence（置信度）。
- 若`is_high_risk=1`且`confidence ≥ τ_ℓ`（阈值在验证集选择），则信号 `s_ℓ(x)=1`。其他字段作为结构化解释保留。
- 结果缓存在知识库中，相同会话ID复用，避免重复调用。

#### d. 证据引导推理与融合
- 骨干输出分数 `a_b(x)` 与阈值 `τ_b`（验证集选择）比较得信号 `s_b(x)`。
- 四个二进制信号（`s_b, s_n, s_r, s_ℓ`）通过选定的融合策略（OR、AND、vote-k之一，在验证集上选择）得到最终决策 `ŷ(x)`。
- 解释生成：收集匹配的局部模式（映射回模板）、触发的规则（带簇解释）、LLM推理依据，形成完整的证据链。

### 公式与算法流程（文字说明）
1. 训练阶段：
   - 骨干独立训练 → 挖掘模式 `K_ngram` → 聚类异常会话 → LLM生成规则 → 验证并存储为 `K_rule`。
2. 推理阶段（每会话）：
   - 骨干预测 → 模式匹配 → 规则匹配 → LLM推理（缓存命中则复用） → 四信号融合 → 输出标签+证据解释。

- **检测效果**：LogSemFuse在所有非完美基线上提升了F1分数；唯一完美案例（LogAnomaly on Liberty）保持不变；平均恢复98.8%的骨干假阴性（2056/2081）。

## 7. 优点

- **即插即用**：无需修改骨干训练或架构，兼容现有检测器。
- **证据可复用**：局部模式和规则在训练时构建，推理时快速匹配；LLM结果缓存，避免了重复调用。
- **基于证据的解释**：解释直接关联可观察的日志行为（模式、规则、LLM推理），而非黑盒特征归因。
- **低成本高效率**：LLM调用集中在一阶段，推理仅需轻量本地匹配+缓存查询。
- **鲁棒性强**：在少数据场景下依然有效，消融实验证明各组件均有贡献且整体稳定性好。
- **用户偏好验证**：通过正式用户研究证实解释质量优于纯LLM基线。

## 8. 不足与局限

- **实验覆盖**：仅使用3个公共数据集（HDFS、BGL、Liberty），可能无法代表所有生产环境（如微服务、跨系统故障、动态模板）。

- **用户研究规模**：14名参与者、10个会话，样本量有限，可能不足以全面反映不同经验和任务场景下的偏好。
- **未考虑部署因素**：未评估实际运维中的告警疲劳、告警排序、告警下钻定位等实用性指标；也未考虑在线学习或模板演化场景。

- **伪节点风险**：HDBSCAN会将离群会话标记为噪声而非聚类，相关异常行为可能无法生成规则。
