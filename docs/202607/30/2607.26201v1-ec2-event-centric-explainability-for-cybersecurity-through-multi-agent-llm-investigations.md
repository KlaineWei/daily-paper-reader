## 摘要
安全运营中心依赖异常检测系统来标记可疑事件。异常检测器的特征级解释对运营调查价值有限。为了有效处理警报，分析师需要了解上下文关系，并对涉及的实体有可操作的理解。本文提出了一种面向事件的、与检测器无关的方法，用于解释中小型企业网络中的网络安全警报。我们提出了(EC)²，这是一个多智能体框架，执行结构化、假设驱动的调查，以提供基于可验证证据的解释。评估结果表明，所提框架通过生成具有操作意义的解释，改进了后检测分析，同时也提高了事件分类的准确性。

## Abstract
Security operations centers rely on anomaly detection systems to flag suspicious events. Feature-level explanations for anomaly detectors offer limited value for operational investigations. To effectively handle alerts, analysts need to know contextual relationships and need actionable understanding of the entities involved. This paper introduces an event-centric detector-agnostic approach for explaining cybersecurity alerts in small- to medium-sized enterprise networks. We present (EC)2, a multi-agent framework that performs structured, hypothesis-driven investigation to provide explanations grounded in verifiable evidence. Evaluation results show that the proposed framework improves post-detection analysis by generating operationally meaningful explanations, which also enhance event classification accuracy.

- **问题**：安全运营中心（SOC）依赖异常检测系统标记可疑事件，但传统特征级解释（如LIME、SHAP）只能说明“模型为何做出决策”，无法揭示“事件本身为何可疑”——例如，一个高报文速率或非常用端口的异常可能源于攻击也可能源于良性配置变更，分析师缺乏上下文和因果理解。

- **核心含义**：需要一种**面向事件（event-centric）、检测器无关**的可解释性方法，提供接近人类分析师推理方式的、基于证据的因果关系解释，从而提升后检测分析效率和检测准确性。

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：采用**假设驱动调查**范式，由多个LLM智能体协作，自动生成假设、检索多源证据、迭代验证，最终输出自然语言调查报告。该报告包含所有探索过的假设、支撑/反驳的证据以及评估结论，而非单一分类结果。
- **关键技术细节**：
  - **多智能体框架(EC)²**：基于AutoGen实现，包含以下关键智能体：
    - **上下文问题生成器**（Investigation Initiation）：根据异常事件信息，生成需补充的事实性问题（如设备身份、通信模式）。
    - **证据收集智能体**：负责将问题路由到对应的**检索智能体**（拓扑图数据库智能体、流量数据库智能体），通过自然语言接口执行Cypher/SQL查询，返回结构化证据。
    - **假设生成器**：基于初始事实，提出最多3个候选假设（攻击、配置错误等）。
    - **规划器**：为每个假设设计需要回答的关键问题。
    - **假设评估器**：基于证据判定假设为“支持”、“反驳”或“未解决”。
    - **流程评估器**：判断是否需继续迭代（最多两轮假设生成，每轮假设最多一次额外证据收集）。
    - **解释生成器**：撰写自然语言报告。
    - **解释评审者**：检查报告完整性和忠实性，可要求修改。
  - **检索增强生成（RAG）**：所有智能体依赖外部数据源（网络拓扑知识图Neo4j + 流量数据库PostgreSQL），避免LLM幻觉。证据检索通过专用检索智能体完成，其他智能体不直接接触数据库。
  - **工作流程**：三个阶段——调查启动（初始事实收集）、调查循环（假设生成→规划→检索→评估→循环，最多两轮）、调查结论（报告生成与评审）。
  - **解释输出**：包含所有假设及其证据支撑状态，不强制选择唯一结论，交由分析师判断。
